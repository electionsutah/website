# Editor UX review

Reviewed November 6, 2026 using the UX Builder skill. Scope: local web editor collection navigation, person record form, field search and section disclosures, and Schema. Assumed primary task: find an entity, locate a field, override its imported value, and save locally. Changes were applied to the existing editor; no separate prototype or dependencies were added. No repository records were published during this review.

The source of truth is `src/app.css`, imported by `elut-theme.mjs`. Confirmed computed Noto Sans form labels and Source Serif 4 record headings in the browser. Preserved the dark navigation, white logo, salmon accent, blue actions, square cards and controls, original social SVGs, and Material Symbols.

## Findings and corrections

These are expert-review findings supported by source inspection and browser observations, not participant research.

| Priority | Finding and task impact | Correction |
| --- | --- | --- |
| High | Decap record shell and toolbar required 800px, putting actions off-screen at 320px. Violates access to the same task across widths. | Removed minimum width at narrow sizes; toolbar wraps in normal flow, and the form fills remaining height. Verified toolbar ends before form content. |
| High | Schema grid expanded to roughly 692px at a 320px viewport. | Allowed grid children to shrink and navigation to wrap. Confined horizontal scrolling to the data table; made its region named and keyboard focusable. |
| Medium | Long field labels forced overflow or displayed unnecessary scrollbars. | Kept single-line labels at wide widths; allowed narrow labels to wrap and removed label scrolling. |
| Medium | Field validation errors were visible but absent from input descriptions. | Added stable error IDs and included them in `aria-describedby`. |
| Medium | Record view lacked a main landmark and started at heading level two. | Added named main region, record H1, and section H2 headings. |
| Medium | Repository live status was rebuilt every two seconds even when unchanged. | Unchanged successful status responses no longer rebuild the live region. |
| Medium | Some toolbar styles retained Decap colors and enabled input boundaries were faint. | Applied ELUT action tokens; enabled control border uses `--color-subtle`. |
| Low | Disabled Schema save button faded text through opacity. | Uses explicit ELUT muted/paper tokens without opacity reduction. |

Reduced-motion styling disables editor transitions and animations when requested. Extra bottom padding keeps the end of the form reachable above the repository status bar.

`npm run check`: zero Svelte errors or warnings. JavaScript syntax checks and `git diff --check` passed. The skill static checker found zero errors; Schema passed, while the Decap HTML bootstrap produced two expected warnings for headings/main generated by JavaScript. The rendered record main and heading hierarchy were separately verified.

## Remaining work and limits

- People expose distinct top-level and contact website/social fields under duplicate display labels. This is observed UI ambiguity; do not merge stored fields without deciding their intended meaning. Clarify labels or consolidate with an explicit data migration.
- Resources and links still require JSON entry. Predictably harder for routine editing and recovery; a row-based list editor would reduce format knowledge and typing errors.
- Existing provenance disclosures still use details instead of the site's evidence popover. A shared implementation for Decap and the site remains a design-system gap.
- Legacy editor CSS still contains hard-coded fallback styling beneath the shared theme. Consolidating those styles would reduce future override conflicts.
- Review was sampled, not a complete audit of every collection, toolbar menu, media dialog, save failure, or status state. No screen-reader session, physical-device test, full 200% text/400% zoom pass, axe/Lighthouse scan, or measured Core Web Vitals run was performed. No installed axe/Lighthouse tooling was found, and no audit dependencies were added. Reduced-motion behavior was implemented but not emulated in this pass.
- No user sessions were conducted. Suggested task test: locate a town, add a missed social account, find a contact field by search, recover from an invalid resource entry, and save. Observe hesitation around duplicate labels, imported/override/clear modes, and save status with keyboard and touch users.

The quality target is WCAG 2.2 AA; this scoped review does not establish full conformance.

## Primary guidance checked

- [WAI-ARIA accordion pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/): native heading buttons, expanded state, controlled panels, Enter/Space and Tab operation.
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/): reflow, contrast, focus, labels/errors, keyboard access, status messages and target size.
- [HTML Living Standard](https://html.spec.whatwg.org/multipage/): native form and document semantics.

## Follow-up: structured editing

The duplicate-label and raw JSON input findings are now addressed. Campaign and
Directory labels identify the site location controlled by each website/social
field; inline help explains their use and directory precedence. No data paths or
stored records were merged. Resources and link/source records now use named row
inputs with add/remove actions, optional link metadata, draft retention, and URL
validation. Existing metadata survives unrelated row edits. The imported/raw
record inspection remains read-only.

`node editor/widget-check.mjs` verifies distinct labels, row creation, invalid URL
recovery, removal, filtered draft retention, and metadata preservation. Svelte
checks pass. These follow-up controls have not received another browser or
screen-reader pass.

## Follow-up: canonical person links

People now expose only one Websites and social accounts list. Both the contact
card and directory cards consume that canonical list. Current imported contacts
and verified links are combined before manual edits are applied; identical URLs
are deduplicated, distinct accounts and enrichment metadata are retained. Manual
list clearing cannot reintroduce the old contact fallback. Historical contact
fields stay on Filings. Legacy person platform/contact overrides and retired
schema presentation settings are handled compatibly. The temporary Decap
integration checks passed, including save, regeneration, inheritance, clearing,
and legacy conversion; no production records were changed by the tests.

## Follow-up: stylesheet ownership

Removed the legacy hard-coded palette/font fallbacks and obsolete blue-logo
header styling. Icon-font registration and shared icon/logo sizes now have one
owner in `elut.css`; collection icon adapters share one rule instead of repeated
font/grid declarations. Consolidated duplicate pane-heading and responsive toolbar
rules. Schema spacing/type values use ELUT tokens, and overridden presentation
defaults were removed from its layout stylesheet. CSS parsing, token-reference
checks, and widget checks pass. This cleanup did not include another visual
browser pass.

## Follow-up: entity image fields

People, offices, parties, and places now expose their images with previews and
Decap's image picker. Photo/emblem credits are editable; new sources clear the old
credit values, while Use imported value restores them. Clear suppresses place
photo fallbacks. Shared image resolvers keep person avatars, detail views, and
place cards consistent with saved overrides.

New uploads use `public/images/uploads/`; imported image locations remain intact.
A scoped API handles upload-library reads and writes; assigned uploads cannot be
deleted, collisions cannot overwrite existing files, and writes are limited to the
upload directory. A direct companion-site route serves new uploads immediately.

Validated with Svelte checks, production build, temporary Decap integration tests,
widget image-selection/reset checks, media path/collision/deletion checks, and a
live upload/list/read/delete round trip against :8080 and :5174. Temporary uploads
were removed and manual overrides were unchanged. These image controls have not
received a visual browser or screen-reader pass.

## Follow-up: image destination folders

The local media-library adapter now provides a Destination folder selector shared
by the Media menu and image-field pickers. It discovers existing `public/images/`
subfolders, including county/place folders, and starts in the current image's
folder when possible. Menu usage offers Copy image URL; record usage offers Use
image. The native dialog provides Escape handling, modal focus containment, and
focus restoration. Original files cannot be overwritten; library deletion remains
limited to the original uploads folder API.

Picker tests verified folder discovery, chosen-folder uploads, selection, and
public-path insertion. Live API checks discovered 43 folders and verified test
uploads in `images/people` and `images/places/cache` on both :8080 and :5174.
Temporary test files were removed; manual overrides were unchanged. Svelte and
storage-isolation checks passed. No additional visual-browser pass was performed.
